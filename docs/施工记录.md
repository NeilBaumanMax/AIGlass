## 步骤 3 · 板端音频、唤醒与千问（2026-11-22）

- 添加板端 Python 常驻客户端：ALSA 双声道采集后取左声道，16 kHz PCM 经 Wi-Fi 上传；电脑本地 Vosk 识别“当时的中文唤醒词（已停用）”，唤醒后播放“我在，请说”。
- 本地处理模式切换、结束对话和无摄像头提示。普通问题调用百炼北京地域 Qwen3-Omni-Flash，接收文本和 24 kHz 音频，回传板子喇叭播放。
- 使用设备令牌、连接会话和音频序号；断线后旧会话和旧回答失效。视觉提醒可插播，已接收音频不在每次心跳中重传。
- 播放期间暂停识别，结束后保留 0.6 秒余音缓冲；这是半双工抑制回声，不是声学回声消除算法。
- 用户在管理员 PowerShell 放行热点网段的 TCP 7860；板子访问 `192.168.137.1:7860` 实测 HTTP 200。
- 修复后台进程随 ADB 会话退出的问题，改用 start-stop-daemon。板端 PID 的父进程为 init，持续采集、播放和上报。
- 排除旧版后台服务占用 127.0.0.1:7860 的冲突，当前浏览器和板子连接同一个服务。
- 10 项回归测试和 Python 编译检查通过。真实千问音频请求成功，返回 24 kHz、约 9.92 秒 WAV。
- 在没有浏览器请求驱动的情况下，实机事件已记录：识别“当时的中文唤醒词（已停用）”→“我在，请说”播放完成→识别“介绍一下你自己”→真实千问文本→板端播放完成。此次回答生成约 5.4 秒，播放约 17 秒。实际听感待用户确认。
- 诊断录音发现远处语音电平低，提高 ADC ALC 左声道增益、MICBIAS 并启用高通。实际近距离唤醒已经成功，调整后的误唤醒、削波和远距效果仍需复测。
- 密钥保存在忽略的 `.env`；令牌、配置和诊断录音保存在忽略的 `.local/`，不提交 Git。
- IMX415 尚未到手，尚不能声称摄像头、真实画面分割或实际通行提醒验收完成。
- 无界面 Edge 实测状态页：显示音频在线和麦克风电平，输入控件数量 0，写入请求数量 0，页面脚本错误 0。截图仅保存在 `.local/dashboard.png`。
- `scripts/deploy-device.ps1` 实机部署通过，能停止旧客户端、更新配置和代码并启动。电脑后端重启后板子自动重新握手，恢复麦克风上传并完成连接提示播放。

## 步骤 3a · 连续对话 8 秒退出

- 用户已确认实际听到唤醒提示和 AI 回答。此前 20 秒等待下一句话的设计容易持续接收环境谈话，用户选择保留连续对话，但将空闲退出时间改为 8 秒。
- 计时从语音播放完成后开始；AI 生成和播放期间暂停超时判定。识别到新增的语音内容会延长等待，相同的残留识别文本不会不断重置计时。
- 到时清理对话上下文并播报“对话结束”，重新等待唤醒；未唤醒的片段不发送千问。网页显示剩余等待秒数。
- 新增三项回归：播放完成后 8 秒退出、等待云端期间不误退出、新语音续期但残留文本不续期。共 13 项测试通过。
- 新版后端已启动，板端已自动重连。已请用户实测模式切换、超时播报和无摄像头提示，真人验收结果待补记。

## 步骤 4 · 实机重启、唤醒回归与超时验收

- 软重启实测，boot ID 改变，Wi-Fi 自动恢复到 `192.168.137.54`，音频客户端由 init 启动并自动完成连接提示播放。原有 Buildroot 可运行当前音频 Demo，无需为这一步重新烧录。
- 第一次重启后的观察中出现两次短暂联网异常，客户端自动重连。为减少实时音频延迟，在每次成功连接后关闭 Wi-Fi 省电；此设置在后续重启后已确认生效。尚未做长时间弱网测试。
- 用户反馈后续唤醒无回应。恢复已成功过的麦克风参数：SingadcL、ADC ALC 左声道 6、MICBIAS 4、高通关闭；放弃前一阶段提高增益的实验配置。
- 唤醒改为连续两个音频块的部分识别结果匹配后立即回应，避免必须等到环境静音才结束识别；兼容常见同音字。新增回归测试，共 16 项通过。
- 用户再次试说，明确确认“能听到唤醒回应”。不能仅凭这次结果把此前问题归因于增益或句尾检测中的某一个因素。

- 使用合成语音和真实 Vosk 模型进行独立集成验证，唤醒成功，模拟播放结束后 **8.23 秒**生成退出提示。这是补充测试，不计作真人录音验收。
- 最后一次软重启后确认：ADC ALC 左声道保持 6，Wi-Fi 省电为 off，音频与麦克风在线，开机提示播放完成。
