# Edith Demo 施工目标

## 已确定的配置

- 眼镜端为 Luckfox Pico Zero RV1106G3，运行 Buildroot Linux。
- 摄像头为 IMX415-98 IR-CUT Camera，通过 CSI 排线连接。
- 使用板载麦克风收音、外接腔体喇叭播放，Type-C 用于供电和调试。
- 电脑承担 WalkGuide 推理、唤醒识别及语音网关。新增目标：AI 会话与工具执行统一进入电脑 nanoMuse，模型使用百炼北京地域的千问，手机控制沿用 nanoMuse 官方客户端。
- 最新联调顺序：先验证电脑取屏、启动应用、输入和眼镜语音朗读；手机已同账号绑定，但按用户要求稍后联调。
- 当前电脑仅用于开发和联调。开发完成后在另一台 **Windows 11 + RTX 4090** 电脑独立部署后端，眼镜切换到该电脑所在局域网；运行不依赖开发机。GitHub README 和部署指南随代码维护。
- 唤醒词为“嗨，Edith”。明确要求看画面时才向千问发送当前帧。
- 唤醒后支持连续对话。语音播放完成后 8 秒无新指令自动退出并提示；本地持续检测唤醒，未唤醒的音频不发送千问。
- 网页只显示设备状态、原始画面、分割结果、提醒、唤醒状态和对话。
- 网页采用用户参考图的深色青蓝玻璃布局，品牌为 Edith，允许清空对话展示历史；不设置语音/文字输入框。
- 要求语音全双工插话，电脑执行播放参考回声消除；实机验证正常音量唤醒与播报中的打断。
- 浏览器关闭后，眼镜端的语音与视觉功能持续运行。

## 分步验收

1. 固定目标与施工记录。核对 Git 和设备连接，提交文档。
2. 后端持续处理视频，网页变成只读。测试浏览器关闭、多窗口、断流、重连、模式切换后的状态一致性，提交实现。
3. 眼镜音频上行、服务器唤醒及对话、眼镜播报下行。测试顺序、重连、播放回声抑制、提醒优先级、失效结果丢弃，提交实现。
4. 板子烧录和联网，采集真实摄像头、麦克风及喇叭参数。逐项进行实际设备验证并记录。
5. 配置本机百炼密钥，实际验证唤醒、切换模式、普通对话、主动看图、语音回复和网页显示。
6. 发布可复现的 Windows 11 + RTX 4090 部署说明；开发完成后在目标机重建环境、迁移设备连接并重新执行完整验收，记录目标机 GPU、驱动、应用/子模块版本和实测结果。

每个可验证步骤执行“实现 → 测试 → 记录 → Git 提交”。软硬件模拟测试和实机测试分别记录。完整 Demo 以眼镜的实际采集与播报通过为准。

## 最终演示流程

启动电脑后端与眼镜服务，眼镜连接局域网后自动开始视觉处理。网页能看到最新状态与画面。佩戴者说“嗨，Edith”，听到应答后发出“切换室外模式”或“看看当前画面”，眼镜喇叭播放回复。关闭网页后重复上述操作，功能继续运行。断网和恢复时有明确状态变化，过期的画面、指令和语音回复被丢弃。
