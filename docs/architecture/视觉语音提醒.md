# WalkGuide 视觉语音提醒

摄像头尚未到手，目前验证的是软件决策和音频调度。真实路况的识别准确率、提醒时机和佩戴体验仍需接上 IMX415 后测试。模拟场景不接入眼镜的实时视频，也不写入在线服务的事件记录。

## 工作链路

Pico 的 RTSP 画面 → 电脑上的原版 WalkGuide 分割与方向规划 → 多帧确认 → 提醒优先级与冷却 → 本地 WAV → 局域网下发给 Pico 喇叭。

`backend/vision.py` 继续直接使用已固定版本的 WalkGuide。`backend/guidance.py` 只处理识别结果的时间一致性与播报，不修改模型、掩码或上游方向算法。视觉提醒无需唤醒，不经过 nanoMuse、千问或云端 TTS；预先生成提示音后，断开互联网仍可工作，但需要眼镜与电脑的局域网连接。

## 播报内容与时机

| 识别结果 | 播报 | 连续确认 | 同一结果再次提醒 |
| --- | --- | --- | --- |
| 台阶 | 前方疑似台阶 | ≥3 帧，跨度 ≥0.2 秒 | 至少 8 秒 |
| 障碍 | 前方有障碍 | ≥3 帧，跨度 ≥0.2 秒 | 至少 8 秒 |
| WalkGuide 通道不足或不确定 | 请暂停，前方通道不明确 | ≥3 帧，跨度 ≥0.2 秒 | 至少 8 秒 |
| 路面不清 | 前方路面看不清 | ≥5 帧，跨度 ≥0.8 秒 | 至少 8 秒 |
| 左 / 右 / 向前 | 前方通道偏左 / 偏右 / 向前 | ≥3 帧，跨度 ≥0.6 秒 | 至少 12 秒 |

优先级依次为台阶、障碍、暂停、路面不清、方向。每次只播一句，采用短句，避免覆盖环境声音。同一帧重复处理不累计确认帧数；高帧率也不能绕过时间确认。危险降为较低等级或普通方向时，至少持续一致 1 秒，减少临界位置来回切换。

新确认的危险可以中断 AI 回答，并取消正在执行的 nanoMuse 任务，迟到的回答不会覆盖提醒。较低优先级不截断正在播放的台阶提醒；已经提醒过的持续危险不会每 8 秒强制打断对话，而是在空闲时、仍有新鲜证据时重复提醒。

普通方向在对话、思考、播报期间延后。空闲后重新核对最新结果，不播放积压的转向指令。一般提醒之间至少相隔 2.5 秒，普通方向及恢复提示之间至少相隔 4 秒；更高等级的新危险可立即越过该间隔。所有时间从软件发出提醒计算，另有确认时长、推理及网络延迟，并非实测端到端响应承诺。

## 没有画面或播放失败

- 模型就绪、音频连接后仍无有效结果，等待 8 秒，再提示一次“摄像头未连接，视觉提醒未启用”。模型加载中保持等待，不据此报方向。
- 有过画面后，距最近用于提醒的图像采集时间超过 **1.5 秒**，停止使用该结果、撤回旧播报命令，并提示一次“画面中断，视觉提醒已暂停”。这个状态也包含推理来不及产出新鲜结果，不专指摄像头掉线。
- 推理异常时提示“视觉处理异常，提醒已暂停”。恢复后先重新确认；普通场景提示一次“视觉画面已恢复”，新危险直接提醒，不等待恢复提示。
- 切换室内/室外、摄像头断线或来源地址改变时，清除旧证据和待播方向。正在计算的旧来源结果不能进入新来源状态。
- 喇叭离线、提示音文件缺失不算已发出；对话占用会重试。设备明确回报播放失败后允许重新发送。网页事件“已播放”表示客户端回报播放命令完成，是否真的听到仍以实机验收为准。

图像预览的过期阈值仍为 4 秒；语音提醒使用更严格的 1.5 秒。预览短暂有画面而语音暂停，可能是推理或视频已经变慢，应看提醒状态与后端日志。

## 验证与调参边界

运行 `python -m unittest discover -s tests -v`。测试覆盖闪烁、重复帧、过期图像、优先级、持续危险重复、对话延后、来源切换、断流恢复、设备协议及播放失败重试。不需要摄像头、显卡或云端调用。

运行 `python scripts/check-guidance.py` 会在本机生成：

- `.local/guidance-demo/report.json`：57 秒逻辑时钟下的场景、每次调度结果、取消 AI 的时刻和模拟播放回执。
- `.local/guidance-demo/preview.wav`：开头说明“以下是模拟场景测试，不是实际路况”，随后播放实际队列发出的提示语。间隔压缩为 0.45 秒，不能用试听文件测量提醒延迟。

场景从无画面开始，依次为偏左、障碍、台阶、暂停、断流和偏右恢复。第 18 秒模拟 AI 思考，第 20.2 秒新障碍取消该模拟任务；重复障碍等对话空闲后再发出。脚本中的断言验证顺序、间隔、延后与取消，并检查没有生成任何相机画面。它不启动在线服务、不连接板子、不采集麦克风、不调用云端；播放成功是模拟回执，不能算喇叭实测。可用 `--output` 更改报告目录。

网页的“视觉语音提醒”卡片来自 `/api/status` 中的 `guidance` 对象，包含当前有效状态、候选/确认结果、发送结果及最近发出的文本。`accepted` 代表进入播放调度，不代表人已经听到。电脑断线后显示状态未知；旧后端没有该字段时显示“策略待加载”，不猜测提醒已启用。

本地提示语从 `backend.speech.PROMPTS` 生成，更新代码后执行 `./scripts/make-prompts.ps1`，再正常启动后端；运行中的服务缓存了旧提示音，修改文件不会自动加载。生成时使用 Windows 中文 Huihui 语音。

以上是 Demo 初始参数。当前输入只有图像分割类别和图像空间的候选方向，没有米制距离、行走速度、身体宽度或目的地。因此不播报“距离 3 米”“可以安全直行”等未经测量的结论。接入真实摄像头后先在静止、有人协助的场景逐项核对识别与播报，再根据实测修改 `backend/guidance.py` 的阈值。
