# 目录与开发约定

| 路径 | 职责 |
| --- | --- |
| `backend/` | 电脑后端：HTTP、视觉、语音、状态机、AI 客户端、持久化 |
| `backend/paths.py` / `config.py` | 根目录定位与本机 `.env` 加载，不在业务文件拼开发机绝对路径 |
| `static/` / `templates/` | Flask 网页资源和模板；网页展示状态，唯一写操作是清空展示记录 |
| `device/` | Pico Linux 音频客户端、启动服务、Wi-Fi 兼容与关键词配置 |
| `integrations/nanomuse/` | 有版本约束的 nanoMuse 桌面桥接源码与许可 |
| `scripts/` | `setup-*` 安装、`install-*` 组件、`check-*` 验证、`deploy-*` 板端部署、`start-*` 启动 |
| `tests/` | Python 回归与 nanoMuse 桥接测试；模拟输入必须明确标记 |
| `vendor/walkguide/` | 固定提交的上游子模块；不能只改 SHA 而不测试适配 |
| `docs/` | deployment 部署、development 施工、architecture 机制、qa 验收 |
| `.venv/` | 新部署统一使用的 Python 3.11 环境；不提交、不跨电脑复制 |
| `models/`、`.tools/` | 下载的模型与工具；不提交 |
| `.local/` | 运行状态、提示音、日志、录音、截图和安装缓存；不提交 |
| `.runtime/`、`.bootstrap/` | 现有开发机的历史运行/引导环境；新部署无需这些目录 |

根目录只保留 README、依赖/配置、Git 文件和启动入口。`app.py` 是兼容入口，新的实现放入 `backend/`；标准启动方式为 `start.ps1` 或 `python -m backend`。`static/` 和 `templates/` 保持 Flask 常规位置，避免无收益的路径改动。

## 开发顺序

1. 查看 [当前状态](当前状态.md) 与 [下一步开发](下一步开发.md)，明确本次验收级别。
2. 从干净工作区创建 `codex/任务名` 分支；保护用户已有修改。
3. 实现后运行对应测试。后端公共路径、会话或语音改动需要完整 Python 回归；模型适配再跑 `check-vision.py`；提醒逻辑跑 `check-guidance.py`。
4. 文档改动执行 `python scripts/check-docs.py`；目录改动验证外部工作目录启动和网页资源。
5. 同步状态表及施工记录，注明使用真实设备、模拟数据还是仅检查代码。记录已提交和已部署的区别。
6. 检查 Git diff 与密钥排除，每个可验证步骤提交。发布前确认当前代码与文档、子模块版本匹配。

程序读写的固定文件（例如 `.local/device-token`、`events.sqlite3`、`nanomuse-turn.json`）不能为美化目录随意移动。新的临时下载放 `.local/downloads/`，测试证据按任务使用 `.local/任务名/`。历史录音、备份和运行目录本次保留，不自动删除未知文件。
