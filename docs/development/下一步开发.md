# 下一步开发

更新日期：2026-11-23。按顺序开展，每个任务单独记录“实现 → 测试 → 证据 → 提交”；当前状态见 [状态表](当前状态.md)。

## 1. 在正常重启后验证当前版本

前置：从原运行终端正常退出旧后端；nanoMuse 使用带 Edith 接口的启动脚本运行。不要并行启动两个服务争用 7860，也不要终止未知进程。

步骤：更新源码与子模块，重新生成提示音，执行预检与回归，使用 `start.ps1` 启动。确认网页出现 `guidance` 状态，板子重新握手，正常音量唤醒，读取电脑记事本，再验证 8 秒退出。

通过标准：记录提交、操作系统/GPU、板子 IP、模型与音频状态；用户实际听到回应与内容；没有摄像头时明确显示等待，不产生方向提示。离线策略测试通过不能代替本项。

## 2. 摄像头未到货时继续完成的任务

| 任务 | 实施与证据 | 通过标准 |
| --- | --- | --- |
| Agent 插话取消 | 回答中说“停一下”；在可取消的电脑任务中插话，检查原 turn 终态 | 停播、原任务取消结果可核实，迟到回答不覆盖新指令 |
| 语音确认 | 使用可恢复的本地测试操作触发工具确认 | 只批准当前 approval_id；无回答、拒绝、过期不会执行 |
| 网络与重连 | 先记录健康连接，短时断开测试网络再恢复 | 网页离线、重新握手、旧回答失效、能再次唤醒 |
| 长时音频 | 持续运行并记录心跳、播放失败和唤醒样本 | 给出观察时长与失联次数；不以几分钟观察宣称长期可靠 |
| 新电脑安装演练 | 在独立 Windows 11 机器按完整部署指南执行 | 不依赖开发机的 `.runtime`、密钥、模型目录、IP 或账号状态 |

真人录音前说明时间和用途，使用倒计时，等待使用者准备；录音和截图仅存本机。不要因为一次无语音样本就提高唤醒阈值。

## 3. IMX415 到货后

1. 断电安装，核对排线、设备树、驱动、IQ/ISP 和 rkipc；先证明真实 RTSP 出图。
2. 网页原图与分割对应同帧；切换室内/室外，验证相机断流与重连。
3. 静止、有人协助的已知场景中核对障碍、台阶、方向与不确定状态；记录原始识别、确认延迟、发送时间和实际听到的语句。
4. 核对频繁转头、低照度、喇叭播放和语音对话时的误报/漏报，再调整提醒参数。
5. 最后同时运行视频与双向音频做持续测试。没有测距传感器时不加入米制距离或“安全通行”承诺。

## 4. 手机与 4090 验收

手机操作按用户要求排在电脑之后。准备手机在线，在 nanoMuse 官方客户端配置相同账号及千问；先打开指定 App、读取实际页面，再验证取消与确认。4090 电脑迁移后重做上述适用验收，不能继承开发机的硬件通过结论。
